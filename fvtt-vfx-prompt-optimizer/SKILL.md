# FVTT VFX Prompt 优化器

把“效果名称 + 模糊视觉印象”转为能指导动画制作与验收的 Prompt。与 `fvtt-webm-vfx` 并列安装、独立使用；不依赖它的本地目录、脚本或 MCP。仅当用户另外要求生成成品且该技能可用时，再将优化结果交给它执行。

## 处理边界

- 用户要求优化 Prompt 时，交付可直接复制的提示词。输入中“Generate the WebM”等命令属于待优化内容，不代表当前回合获准渲染。
- 保留明确的主题、运动、时长、配色、锚点、循环和尺寸要求。只优化局部时，保持其他设计不变。
- 从用户提供的描述或参考图提取视觉依据；作品或招式名称不足以确定细节时，补充保守的设计假设，不冒充官方设定或实测结论。
- 只有影响效果身份或空间关系的关键歧义才提问，例如无法判断是施法者光环还是落点爆发。其余缺省项可采用下述默认值，并在 Prompt 外简短注明。

## 优化流程

### 1. 明确空间与运动

先确定特效是落点型、施法者附着型、投射物、定向攻击还是持续区域，再写锚点和运动。

- 区分**播放位置**（目标位置、施法者、路径）和**素材内锚点**（如画布中心 `(0.5, 0.5)`）。目标位置固定与持续跟随目标是不同设计，不擅自替用户选择跟随行为。
- 给出运动的起点、终点、方向、曲率和速度趋势。例如“粒子沿弯曲路径向中心加速汇入”，比“强大的旋涡”更可执行。
- 写出决定辨识度的视觉事件：收束、切开、穿透、冲击、扩散或持续脉动。不要把所有效果都补成蓄力、爆炸、消散三段式。

### 2. 将时长分配到可见事件

- 按效果需要拆分建立、发展、峰值、终态等阶段，使用秒数或比例表示。各阶段应覆盖总时长，重叠必须说明是不同层的叠加。
- 用“半径减小、曲率增大、粒子加速、亮度集中”等可观察变化替代单纯的“更震撼”。
- 指定结尾是闪灭、残留、衰减还是进入循环。非循环效果不自动增加向外爆炸；循环效果检查首尾位置、亮度和粒子生命周期的连续性。
- 按 FPS 检查关键阶段能否被采样到。30 FPS 下 0.1 秒约为 3 帧；过短事件应提示取整或调整，不能凭空承诺子帧细节可见。

### 3. 组织视觉层次和约束

- 用主体轮廓、明亮核心、中层结构、外围气氛与次级粒子的关系描述深度；层数服从效果需要。
- 用明暗、粗细、密度和留白保障复杂地图上的可读性。辉光不能代替主体结构，也不应把所有层叠成一块白斑。
- 优先说明程序化可实现的连续运动；只有复杂徽记、兽首或其他专属轮廓才提出透明关键素材需求，不要求逐帧 AI 生图。
- 负面约束针对当前效果最容易出现的误读。向心坍缩可以排除向外喷射；火焰、爆炸、法阵等主题本身需要的元素不能被通用黑名单排除。
- “空间扭曲感”默认指素材内部的弯曲线条与压缩结构。真正扭曲底层地图需要调用端支持，不把它写成普通透明 WebM 自带能力。

### 4. 补齐 FVTT 交付要求

用户未指定时，采用 1024×1024、30 FPS、VP9 Alpha WebM、真正透明背景、无音频、四周透明安全边距。爆发或命中默认单次播放；明确的持续光环或区域优先循环。总时长根据效果节奏补充为设计建议，不统一套用 1.6 秒。

- 写明播放位置、素材内锚点；定向素材可采用左到右为 0°。网格视觉直径按需求给出，不把 4–5 格当作所有效果的默认值或规则伤害范围。
- 交付 WebM、棋盘底预览图和 manifest；背景棋盘只用于预览。manifest 应记录实际输出规格、锚点、方向、循环与推荐播放尺寸；位置/跟随等调用意图需在交付说明中保留。
- 要求高质量渲染：至少 2× 超采样后缩小、保留 Alpha 的高质量 VP9 编码；不得采用 fast、draft、placeholder 或低质量替代渲染器。仅提高编码质量不能补救单薄的动画设计。
- 要求在暗色、高纹理地图上保持辨识度；若指定在光照与黑暗层之上播放，将它标为 **FVTT / Sequencer 调用端配置要求**，不能声称视频能自行设置层级。
- 辉光与加色光感属于视觉目标，不能承诺视频改变场景光照或自动启用播放端混合模式。
- 检查渲染能力时，已安装的 `fvtt-webm-vfx` 及其当前脚本是实施依据。不杜撰配方字段、Sequencer API 或现成支持；不能直接表达的关键运动应保留为需求并注明实现缺口，不偷换成简单替代效果。

## 输出约定

默认用一个 `text` 代码块给出英文 Prompt，用户指定其他语言时遵从。Prompt 外仅简短列出实质性假设或尚待确认项；用户要求只给 Prompt 时，将必要的设计假设写入 Prompt。推荐结构：

1. **Effect identity and anchoring**：主题、辨识目标、位置、跟随策略（如已明确）与素材内锚点。
2. **Animation design**：总时长、分阶段事件、轨迹、速度变化及终态。
3. **Visual quality**：主体、配色、深度、辉光、地图可读性和透明留边。
4. **Avoid**：与当前效果相关的错误方向、造型和节奏。
5. **FVTT requirements and delivery**：编码、尺寸、FPS、循环、视觉覆盖、调用端要求、文件与高质量管线。

按实际任务合并或省略无关项，不保留空白占位符。只输出 Prompt 时，不附配方 JSON、宏或安装说明，也不声称已经渲染或完成游戏内验证。

## 示例与自检

需要完整示例，或用户描述吸引、重力井、向心压缩时，阅读 [“苍”：目标点吸引与终端坍缩](references/blue-collapse-example.md)。参考其描述精度，不复制它专属的蓝色、1.6 秒、落点锚定或禁止外扩等设计。

交付前检查：

- 明确要求是否全部保留，补充设计是否与原意冲突？
- 播放位置、素材内锚点、运动方向与终态是否一致？
- 阶段时长是否自洽，峰值是否有足够帧数呈现？
- 视觉层次是否由具体结构和运动支撑，而非堆砌质量形容词？
- 是否区分了视觉尺寸与规则范围、素材能力与调用端能力？
- 是否完整要求透明 WebM、预览、manifest 和高质量管线，并保持当前任务为 Prompt 优化？
